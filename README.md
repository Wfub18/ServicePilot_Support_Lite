# ServicePilot Support Lite

Небольшое веб-приложение с чатом AI-администратора компании ServicePilot Support. Работает локально и подготовлено для Vercel. Пользователь задаёт вопросы об услугах, ценах и времени работы, а сервер передаёт историю диалога в OpenAI Responses API.

## Требования

- Node.js 24.x;
- OpenAI API key.

Сторонние npm-пакеты не используются, поэтому устанавливать зависимости не требуется.

## Настройка и запуск

1. Скопируйте `.env.example` в новый файл `.env`.
2. В `.env` замените `your_openai_api_key_here` на ваш ключ:

   ```env
   OPENAI_API_KEY=ваш_ключ
   OPENAI_MODEL=gpt-5.4-mini
   PORT=3000
   ```

3. Запустите приложение из папки проекта:

   ```powershell
   node --env-file-if-exists=.env server.js
   ```

4. Откройте в браузере [http://127.0.0.1:3000](http://127.0.0.1:3000).

При наличии npm можно также использовать `npm start`. Файл `.env` добавлен в `.gitignore`, поэтому ключ не попадёт в репозиторий.

## Основные файлы

- `server.js` — локальный сервер, системная инструкция, запрос к OpenAI и обработка ошибок;
- `public/index.html` — структура интерфейса;
- `public/styles.css` — адаптивное оформление;
- `public/app.js` — логика чата и история текущего диалога;
- `.env.example` — пример настройки переменных окружения;
- `package.json` — команды запуска и проверки.

## Обработка ошибок

Если OpenAI API недоступен, превысил время ожидания или вернул пустой ответ, чат покажет понятное сообщение и останется доступен для повторной отправки.

## Схема Vercel

`public/` раздаётся как статика; `api/chat.js` экспортирует общий с локальным
сервером Node.js обработчик `/api/chat`. Импорт `server.js` не открывает порт.
Интерфейс, системная инструкция и NDJSON-события `reply`/`error` сохранены.
При повторной попытке клиент получает NDJSON-событие `status: retrying`.
Всего допускаются до пяти попыток; задержки — 1, 2, 4 и 8 секунд плюс jitter до 100 мс.
Повторяются только распознанные временные сетевые ошибки и подходящие HTTP
408, 429, 500, 502, 503, 504. Для 429 требуется распознанный код ограничения частоты;
ошибки квоты, оплаты, авторизации и параметров не повторяются. Retry-After для
429/503 учитывается в секундах или формате HTTP-date; если задержка не помещается
в оставшийся бюджет времени, повтор не выполняется. После успешного HTTP-ответа
ошибки чтения тела и неполные ответы модели не приводят к повторам.
Повтор после неоднозначного сетевого сбоя всё ещё может привести к повторной оплате.
Это по-прежнему NDJSON-ответ после получения полного ответа AI, а не поток токенов AI.

Актуальная документация Vercel поддерживает и backend-фреймворки, и отдельные
[Node.js Functions](https://vercel.com/docs/functions/runtimes/node-js).
Выбрана отдельная Function: существующему приложению на `node:http` не нужны
новый фреймворк, адаптер сервера или правила переписывания всех маршрутов.
Версия [Node.js 24.x](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions)
зафиксирована в `package.json`. `vercel.json` задаёт Other (`framework: null`),
пустые Build/Install Command, Output Directory `public` и `maxDuration: 120`.
Лимит Function оставляет запас для чтения входного запроса и завершения ответа
сверх общего 90-секундного бюджета AI.
При включённом Fluid Compute этот предел укладывается в
[лимиты Hobby](https://vercel.com/docs/functions/limitations).

## Защита и ограничения

- Ключ читается только сервером из `OPENAI_API_KEY`, не передаётся в браузер,
  конфигурацию или логи. Не добавляйте его в `public/`, Git или `vercel.json`.
- В журнал пишутся только фиксированные метки ошибок. Сообщения и причины
  исключений, заголовки, тела ошибок провайдера и история диалога не журналируются.
- До пяти вызовов AI на запрос; максимум 1 200 выходных токенов на попытку.
  [Этот предел](https://developers.openai.com/api/docs/guides/reasoning)
  включает и reasoning-токены. Неполный ответ считается ошибкой.
- Общий таймаут AI — 90 секунд на все попытки, чтение ответа и задержки;
  `OPENAI_TIMEOUT_MS` может только уменьшить его.
  До получения успешных HTTP-заголовков попытка ограничена 30 секундами
  (`OPENAI_ATTEMPT_TIMEOUT_MS`, можно только уменьшить). Это даёт модели время
  на генерацию, но не позволяет одному зависшему соединению израсходовать
  весь общий бюджет. Таймаут отдельной попытки допускает Retry, если бюджет остался.
  Тело неуспешного HTTP-ответа также ограничено таймаутом попытки; неизвестный
  ответ 429 по-прежнему не повторяется без подтверждения временного rate limit.
  После успешных HTTP-заголовков таймер попытки снимается: чтение ответа может
  использовать оставшийся общий бюджет, без Retry при обрыве или таймауте.
  Пять — максимум, а не гарантия пяти запусков при медленных попытках или Retry-After.
  Разрыв соединения с клиентом отменяет ожидание провайдера, но не гарантирует
  отмену уже выполненной работы и оплаты на стороне AI.
- Тело до 100 000 байт; до 24 последних сообщений, до 4 000 символов в сообщении
  и до 16 000 символов суммарно. Локальное чтение тела ограничено 10 секундами.
- На процесс: 6 запросов в минуту с IP, 30 запросов в минуту суммарно,
  максимум 2 одновременных запроса. Превышение возвращает 429 и `Retry-After`.
  На Vercel используется доверенный `x-vercel-forwarded-for`, локально — адрес
  сокета. Поддельный обычный `X-Forwarded-For` локально не учитывается.
- Проверка Origin ограничивает запросы из посторонних браузерных страниц,
  но не заменяет аутентификацию и не блокирует прямые обращения ботов.
- `CHAT_ENABLED=false` отключает чат до вызова AI. На Vercel изменение переменной
  окружения требует нового деплоймента; для немедленной остановки блокируйте
  маршрут в Firewall или приостанавливайте проект.

Счётчики в памяти сбрасываются при холодном старте и независимы между экземплярами.
**Они не обеспечивают общий лимит расходов.** Внешняя БД не используется.

## Перед первым деплойментом

1. Убедитесь, что это личная некоммерческая демонстрация: именно для такого
   использования предназначен [Hobby](https://vercel.com/docs/plans/hobby).
   Для рабочего коммерческого сервиса потребуется подходящий тариф.
2. Выберите корень этого приложения, Framework Preset **Other**, Node.js **24.x**,
   включите Fluid Compute. Настройки сборки берутся из `vercel.json`; не добавляйте
   команду `npm start` в Build Command и не меняйте Output Directory с `public`.
3. В Settings → Environment Variables добавьте существующий `OPENAI_API_KEY`
   только в нужные окружения. `OPENAI_MODEL=gpt-5.4-mini` уже является серверным
   значением по умолчанию. `OPENAI_TIMEOUT_MS=90000` и
   `OPENAI_ATTEMPT_TIMEOUT_MS=30000` необязательны. Если в Vercel уже сохранены
   старые 45000 мс, обновите это значение перед деплойментом. Для первоначальной
   проверки без AI используйте `CHAT_ENABLED=false`; включение потребует redeploy.
   Не переносите `.env` на Vercel. Не выдавайте ключ незащищённым Preview.
4. До публичного включения AI настройте Firewall → WAF Rate Limiting:
   метод POST, путь начинается с `/api/chat` (включая возможные варианты URL),
   ключ счётчика IP, 6 запросов за 60 секунд, действие Rate Limit / отказ.
   Проверьте, что правило включено, а не только пишет в лог. Hobby позволяет
   [одно правило rate limiting](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting).
   Если оно занято, согласуйте его замену или держите чат закрытым.
5. Для закрытой демонстрации включите доступную Deployment Protection; проверьте
   охват production, preview и альтернативных доменов. Для публичного чата лимит
   по IP не защищает от распределённой атаки. Проверьте доступные ограничения
   и уведомления расходов в проекте AI-провайдера: бюджет-уведомление само по себе
   не гарантирует прекращение расходов. Контролируйте usage и возможность
   оперативной блокировки маршрута. Vercel Hobby не оплачивает AI API.
6. Перед отправкой проверьте состав файлов. `.vercelignore` разрешает CLI загружать
   только сервер, Function, четыре файла интерфейса и конфигурацию. ZIP, DOCX,
   `.env*`, тесты и документация в этот список не входят. При Git-интеграции
   репозиторий клонируется для сборки: `.vercelignore` не заменяет Git-фильтрацию.
   Публикуется только `public/`, а `functions.excludeFiles` дополнительно исключает
   документы, архивы, `.env*`, тесты и служебные каталоги из Function.
   Архивы и исходный DOCX сохраняются локально.
7. После отдельно разрешённого деплоймента проверьте `/`, статические ресурсы,
   недоступность `/.env`, `/server.js`, ZIP/DOCX, метод GET на `/api/chat` (405),
   Firewall (429), затем NDJSON с разрешённым тестовым AI-запросом. В этой работе
   ни деплоймент, ни реальные AI-запросы не выполняются.

## Локальная проверка без AI

```powershell
npm run check
npm test
npm start
```

Зависимости не нужны. `npm test` использует встроенный `node:test`, локальный HTTP
и заглушки `fetch`, не загружает `.env` и использует только фиктивную тестовую
строку вместо ключа внутри процесса тестов. Не проверяйте AI через рабочий ключ.
При отсутствии npm проверки запускаются напрямую: `node --check server.js`,
`node --check api/chat.js`, `node --check public/app.js`, `node --test`.
Команда приложения — `node --env-file-if-exists=.env server.js` — осталась прежней.
